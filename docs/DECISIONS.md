## 2026-08-24（3日目標・自律実装）

- **距離減衰の基準距離**: SPEC 6.1「発射時距離」は発射時点で相手が未確定のため、実装は **発射位置→命中位置の弾の飛行距離** で判定。実質同じ挙動。差が出るのは相手が弾に向かって走った場合のみ（少し有利判定）。
- **中心ヒット判定**: 弾は1tickに約23unit進むため、「命中時点の距離」だと中心を通る弾でも中心判定にならない。**弾道（直線）と中心の垂直距離**で判定するよう変更（テスト「中心ヒットは1.5倍」で検出）。当たり判定自体は1tickの移動線分で行い、すり抜けを防止。
- **ガード中の被弾**: 三すくみ「射撃＞防御」を「ダメージ0・ゲージ-25」と解釈。ゲージ0で自動的にガード解除＋0.6秒ブレイク。ガードブレイク中は移動・射撃・防御不可。
- **ライフスティール**: Day1は全キャラ共通の「命中で与ダメ50%シールド回復」のみ。スピード型固有の「背面180度限定＋秒間キャップ12」はセイバー実装時（2週間目標）に扱う。
- **被ダメ倍率**: Day1は1.0（標準）。キャラ実装時に1.3/0.85/1.0へ。
- **撃破時スロー0.3秒**: ホストのシミュレーション速度を0.3倍にして実現（見た目だけでなく全員同期のスロー）。
- **中継サーバーのビルド**: tsc の NodeNext だと shared の相対importに拡張子が必要になるため、esbuild でバンドル（`--packages=external`）。
- **フィールド寸法**: 論理1280×720。「画面幅」の%はこの1280を基準。
- **練習モード**: 動作確認用に「的（動かないプレイヤー）」と1人で戦えるモードをタイトルに追加。SPECにはないが、非エンジニアの確認導線として有用なので残す（2週間目標のbot Lv1に吸収予定）。
- **ルームコードの文字**: 0/O/1/I を除いた英数字32種（口頭で伝えやすくするため）。

## 武器を左右クリックに統一（裁定10・ユーザー決定）
- 武器切替という操作を廃止。**左クリック＝主武器 / 右クリック＝副武器**の2枠に統一
  - スピード型: 左セイバー / 右ピストル
  - 重量型: 左HMG / 右ナイフ
  - 支援型: 左「狙撃/ヒール」融合枠 / 右ジャブ
- 支援型は武器3種で2ボタンに載らないため、狙撃とヒールを左クリックに融合。離したときの溜め時間で3分岐:
  - 単クリック（< 0.15秒）= ヒール
  - 0.15〜0.3秒 = 不発（溜めフェイントを維持するための区間・ユーザー案）
  - 0.3秒以上 = 狙撃（威力は溜め時間に比例。従来どおり連続スケール、段階制にはしない）
- 廃止に伴い `weaponSwitchSeconds` と切替クールダウン中の攻撃ロックを削除（「切替直後に攻撃が出ない」不具合の解消を兼ねる）
- キー設定から「武器切替」の行を削除
- 【Claude提案・不採用】ガードで溜めキャンセル → ユーザー案（単クリック分岐）の方が追加ルール不要で優れるため棄却

## 入力ラッチ方式（裁定11）
- 症状: スキル・武器切替が不発になることがある
- 原因: `JustDown` を毎フレーム読んで `inputs` を上書きしていたため、tickが走らないフレームで拾ったエッジが次フレームに踏み潰される。描画は144Hz等でも sim は60Hz固定なので、高リフレッシュレート環境ほど頻発。ゲスト側も送信60Hzで同じ取りこぼし
- 対処: 押した瞬間をラッチ（フラグ保持）し、**tick／送信が必ず1回消費してから消す**方式へ変更
- 【Claude提案・ユーザー承認】tickRateの144Hzへの引き上げは棄却。原因がレートではなく取りこぼしであること、ホスト権威型でホストPCの負荷が2.4倍になること、既存の裁定・テスト70本が60Hz前提であることが理由。60Hzでの遅延は最大16.7msで体感不能

## 世界スケール 2/3（裁定12・ユーザー決定）
- キャラ・武器リーチ・スキル範囲・静穏オーラ・弾サイズ・弾速・移動速度を**一律 2/3**に縮小。時間とダメージは不変
- フィールド寸法(1280×720)は据え置きのため、キャラ基準ではアリーナが1.5倍広くなる（横断: 速1.8秒/重3.0秒/支2.25秒）
- 間合いの関係（何キャラ分でリーチが届くか）は完全に据え置き＝戦い方は変わらない。「移動している時間の割合が増える」のが唯一の変化
- 実装: `balance.ts` の `WORLD_SCALE` 定数1箇所。`px()` / `ratio()` / `cross()` を通して適用しており、`1` に戻せば旧スケールへ即復帰できる
- 実プレイで散漫に感じた場合はフィールド側を縮める方向で調整する

## 近接を棒の掃き判定に（裁定13・ユーザー決定）
- 旧: 決められた時刻に扇全体が一瞬光る点判定
- 新: **キャラ中心から伸びた棒が扇を掃き、棒が横切った相手に当たる**。判定・見た目の両方を変更
- パス設計（中心を横切る時刻が旧仕様と一致するよう調整＝手触りを維持）:
  - セイバー: **2往復＝4パス**（各0.1秒）。中心通過 0.05/0.15/0.25/0.35秒＝旧hitTimesと完全一致。多段4ヒットを視覚化
  - ナイフ: 1パス（0.15〜0.45秒）。中心通過0.3秒＝旧hitTimeと一致
  - ジャブ: 1パス（0.03〜0.13秒）。中心通過0.08秒＝旧hitTimeと一致
- ダメージ量は不変（単発武器は扇内の相手をいずれ棒が通過するため）。変わるのは扇の端にいる相手に当たるタイミングのみ
- ジャブの扇を **0.7 → 1.0ラジアン**（片側40度→57度）に拡大。範囲が見やすくなる代わりに支援型の近距離自衛は強化側に動くので、実プレイで要観察
- マーク回収の「初撃」判定は、スイング全体の初撃から**相手ごとの初撃**へ変更（掃き方式に整合）

## ESCメニューと訓練場のリセット（裁定14・ユーザー決定）
- 常設の退出ボタンを廃止し、**ESCキーでメニュー**を開く方式に。退出の確認ステップは無し（ユーザー決定）
- メニュー表示中もゲームは止めない（オンラインで止められないため挙動を揃える）。開いている間は操作入力を無効化してクリックの誤爆を防ぐ
- 訓練場: リセット / ゲージ全快 / キー設定 / 閉じる / 訓練場から退出
- 対戦: 閉じる / マッチから退出
- **訓練場に経過時間の概念を持たせない**（HUDの時計を「訓練場」表示に置換）
- リセット = 訓練場に入り直したのと同じ状態。ゲージは**ゼロ**で戻す
- 「ゲージ全快」はリセットとは別項目として独立（ユーザー決定）。リセットと補給は目的が違う操作なので混ぜない
- 【Claude提案・不採用】リセットでゲージ全快 → 実戦のゲージ管理が練習できなくなるため棄却

## ESCメニューの作り直し（裁定19）
- 症状: メニューの「退出」が効かない
- 原因: メニューを生成して `setVisible(false)` で隠す実装だったため。Phaserでは非表示コンテナの子が入力を拾い続けることがあり、開閉の状態と入力の状態が食い違う
- 対処: **開くたびに生成し、閉じるたびに完全に破棄する**方式へ変更。背面に透明なブロッカーを敷き、メニュー外のクリックがゲームへ抜けないようにした
- ESCをもう一度押すと対戦画面に戻る（メニュー上部にも明記）
- 文言統一: 「閉じる」→「対戦に戻る」、「訓練場から退出／マッチから退出」→「ホームに戻る」

## 重量型の火力調整（裁定20・ユーザー決定）
- HMGのダメージ 4 → **2**（半減）。理由: キャラの機動が速く弾を当てるのが難しい現状では、連射が効くHMGの当てやすさに対して火力が過大
- HMGのマガジン 40 → **30**
- 副作用の相殺: 重量型のシールドは時間回復せず**与ダメージの回収のみ**が回復源のため、ダメージ半減はそのまま耐久半減になる。これを打ち消すため**重量型のシールド回収率を50%→100%**に引き上げ（`shield.heavyLifestealRatio`）
- 統合ゲージは命中「回数」で稼ぐ仕様なのでダメージ半減の影響を受けない（マガジン30化の影響のみ）
- 【Claude提案・不採用】ダメージ4→3の緩やかな調整 → ユーザー判断で半減を採用

## ビルドウォールとグラウンドスラムの操作変更（裁定21・ユーザー決定）
### ビルドウォール（旧「壁」から改名）
- 押した瞬間にゲージ消費して「構え」に入り、**離した瞬間のカーソル位置に設置**
- 設置可能距離は**最大5キャラ分**（`placeMaxPlayers: 5`）。超えた場合はその距離でクランプ。旧仕様は「向いている方向へ固定約1.5キャラ分」だったので、自由配置化と合わせて大幅な強化。強すぎる場合は3キャラ分へ落とす
- 構え中は**移動もHMGも可能**。**右クリックでキャンセル、ゲージは返らない**
  - 重量型の右クリックはナイフだが、構え中はキャンセル入力が優先されナイフは出ない（ユーザー承認済み）
- 構え中は設置予定位置にプレビューを表示（敵にも見える）
### グラウンドスラム

- ゲージは溜め開始時に消費。中断されても返らない
- 【Claude提案・不採用】中断時のゲージ返却 → 「0.35秒にスタンを合わせるのは現実的でない」というユーザー判断で棄却

## 近接の当たり判定バグ修正（裁定23）
- 症状: 刀・ナイフ・ジャブの「先端に当たり判定がない」ように見える
- 原因: 掃き判定が相手の**中心点の角度**しか見ておらず、相手が半径を持つ円であることを角度側で考慮していなかった。距離は `reach + P.radius` で半径を足していたので、ズレていたのは角度だけ。体が扇に重なっていても中心が扇の外なら当たらず、要求精度が距離によらず一定なので遠い先端ほどシビアに感じた
- 対処: 距離dにおける相手の見込み角 `asin(P.radius / d)` を許容に含める。密着では広く、先端では狭くなり見た目どおりになる
- 副作用対策: 許容を入れると同一パス内で連続tickヒットするため、**1パス1ヒット**の重複排除（`swingPass` / `swingHitIds`）を追加

## 弔い合戦バナーの位置変更と、固まる不具合の修正（裁定29）
### 表示位置
- 「味方ダウン！CD半減中」が画面中央に大きく出て邪魔だったため、**左上の小さな通知**に変更（色・フォントは維持）
- 同様にシステム系メッセージ（退出・リセット・ゲージ全快・処理落ち検知）も左上の通知に統一
- 中央の大バナーは「FINISH」と「LINK!」だけに絞った

### 固まった原因（裁定28の実装バグ・Claudeの実装ミス）
- `state.slamZones`（スラム×スタン／ポーションのリンク受付枠）を**push するだけで一度も破棄していなかった**
- 結果、スラムを撃つたびに配列が伸び続け、
  1. スタン弾・ポーションの着弾判定が毎tick全件走査になり計算量が増え続ける
  2. `slamZones` は SimState の一部なので**20Hzのスナップショットに丸ごと載り、送信量が膨らみ続ける**
- 試合が長引くチーム戦（＝味方ダウンが起きる状況）ほど顕在化するため、弔い合戦の表示と同時に固まったように見えた
- 対処: 毎tickで**期限切れを破棄**し、あわせて**複製**するよう修正（複製漏れは前フレームの状態を書き換える別のバグでもあった）
- 予防: 角度正規化の `while` ループを `normalizeAngle()` に置換。非有限値が入ると `-Infinity + 2π = -Infinity` で永久に抜けられない構造だったため、ガードを入れた

## ソニックの始点リングが飛んでいく不具合（修正・Claudeの実装ミス）2026-08-25
- 症状: ソニック発動時、始点の衝撃波リングが画面の隅へ飛んでいく

## 撃破時にゲームが止まる不具合（修正・Claudeの実装ミス）2026-08-25
- 症状: 撃破が起きると画面が固まり、ESCメニューの「ホームに戻る」なども効かなくなる（「ホームに戻れない」として報告）
- 原因: 撃破ズーム（v1完了時に実装）で `cameras.main.zoomTo(..., "Cubic.Out")` と書いていた。Phaserの**カメラ演出はイーズ名を厳密に照合**するため（`"Cubic.easeOut"` が正）、関数が見つからず次のフレームで例外。Phaserのゲームループは例外が出ると**次のフレームを予約しない**ため、その時点でゲーム全体が停止する
- Tweenの方は同じ表記でも内部で補正してくれるので、気づきにくかった
- 対処: 4か所を `"Cubic.easeOut"` に修正。ヘッドレスブラウザで「練習開始→撃破→ESC→ホームに戻る」がタイトルへ戻ることを確認
- 付随: オンライン退出時 `disconnect()` が `closed` を発火して `leave()` が二重に呼ばれ、タイトルのメッセージが「接続が切れました」に上書きされていた。`leaving` フラグで一度だけにした
- 裁定29の「固まる」報告の一部はこの不具合だった可能性がある

## 効果音の穴埋め3点（裁定37・ユーザー決定）2026-08-25
背景: ドパガキ視点の棚卸しで、(1) 被弾側が無音、(2) 全武器のヒット音が同じ、(3) 撃破音が誰の撃破でも同じ、の3つを構造的な穴として指摘し、まとめて埋めた。
- **被弾音 `hurt`**: 自分が殴られたときに鈍く低い「ドスッ」。中心を取られたときは短い不協和音を重ねる。攻撃側の音（明るく高い）と対照にして、聞くだけで「殴った／殴られた」が分かるようにした
- **武器別ヒット音 `hit(weapon, combo, center)`**: 刀=鋭い斬撃＋金属の余韻／ピストル=乾いたスナップ／HMG=短く重い（連射なので控えめ）／ナイフ=低く湿った刺突／狙撃=長い尾を引く一撃／ジャブ=軽い「ポッ」。連続ヒットのピッチ上昇は全武器共通で維持。中心ヒットは武器音の上に高い抜け音を重ねる方式に変更（以前は武器音を置き換えていた）
- **撃破音の3分岐 `kill("mine"|"me"|"other")`**: 自分が倒した=爆発＋上昇アルペジオ（C6→E6→G6→C7、撃破スロー0.3秒内に鳴り切る）／自分が倒された=低く沈む下降音／他人同士=従来の爆発を小さく遠くで
- sim側: `hit` イベントに `weapon: HitWeapon` を追加（近接はクラスで一意、弾は BulletKind、リンク効果のスタンは "link"）。テスト1本追加
- 次候補（未着手・優先順）: A ゲージ満タン通知 → B 死にスティング＋復活音 → C 多段キル → D 低HP心音（ON/OFF付き） → E トドメの一撃の音

## バレットプルーフとポーションの見える化・ポーション射程（裁定38・ユーザー決定）2026-08-25
背景: 「バレットプルーフが発動していない気がする」との報告。調査の結果、発動しても自機が薄く点滅するだけで専用の音も演出もなく、ポーションも範囲が見えないため、効いているかどうかが判別できない状態だった。
- **バレットプルーフ**: 発動の瞬間に水色のリングが弾けて広がり「PROOF」のポップ＋専用音（ガラスが張るような高い「キィン」）。無敵中は**水色の六角シールド**が対象を取り囲み、残り時間で薄くなる。味方に投げて当たった場合も同じ演出。表示用に `bulletproofT` を追加（無敵の実体は従来どおり `invuln`。攻撃で無敵が解除されたら表示も消える）
- **ポーション**: 構え中に**着弾予定地点へ投擲線と回復範囲の円**を表示（ビルドウォールのプレビューと同じ方式）。飛んでいる間も着弾点に範囲を出し続け、炸裂時は範囲いっぱいに緑の円が広がる＋専用音。回復した相手がいなくても炸裂演出は出す（`potion` イベント）
- **ポーションの射程**: `throwMaxPlayers` 8 → **16**（2倍）
- 調査で見つかった**未決の2点**（ユーザー判断待ち）:
