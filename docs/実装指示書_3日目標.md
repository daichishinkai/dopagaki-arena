# 実装指示書：3日目標（動くもの）

対象：要件定義書v3.2 15章「3日目標」
ゴール：キャラが全方向移動・攻撃（武器1種）・防御でき、2人がルームコードで繋がって互いの動きが見え、HPが減って勝敗が出る。

---

## 0. 全体の進め方（先に読む）

- 1ステップ＝1セッション＝1コミットを原則にする。ステップの途中で別の話題を混ぜない。
- 各ステップの冒頭で **プランモード（Shift+Tab を押して「plan mode on」表示）** にしてから貼る。計画が出たら読んで、納得したら承認して実装に進める。
- 各ステップには「完了条件」と「あなたの確認手順」がある。**確認手順を自分でやって通ったら次へ**。通らなければ、そのエラーや見えた現象をそのまま貼って直させる。
- 同じ問題で2回直しても直らないときは `/clear` して、「〇〇をしたら△△になる。原因を調べて直して」と最初から言い直す。
- 完了したら `git commit` させ、`docs/PLAN.md` を更新させる（CLAUDE.mdに書いてあるので言わなくてもやるはずだが、やらなければ「コミットとPLAN.md更新をして」と言う）。

## 0.5 セットアップ（Day 0・30分）

1. GitHubで空のプライベートリポジトリを作る（例: `dopagaki-arena`）。
2. ローカルにクローンし、そのフォルダに `CLAUDE.md` と `SPEC.md`（要件定義書v3.2を改名）を置く。`docs/` フォルダを作る。
3. そのフォルダでターミナルを開き `claude` を起動。プランモードにして以下を貼る。

```
このリポジトリを初期化して。CLAUDE.md と SPEC.md を読んでから、
CLAUDE.md の「リポジトリ構成」どおりに npm workspaces（client / relay / shared）の骨組みを作って。
- client: Vite + Phaser 3 + TypeScript。起動すると黒い画面に「PvP Arena」と出るだけでよい
- relay: Node.js + ws。起動すると 8080 で待ち受け、接続があればログを出すだけでよい
- shared: TypeScript。balance.ts に SPEC.md 16章の初期値を定数として書き出す（まだ使わなくてよい）
- Vitest を shared に入れ、balance.ts の値が SPEC.md と一致することを確認するテストを1つ書く
- npm run dev / dev:client / dev:relay / test / typecheck / build を用意
- .gitignore、docs/PLAN.md（3日目標のチェックリスト）、docs/DECISIONS.md（空）を作る
終わったら、私が動作確認する手順を3行以内で教えて。まだコミットはしないで。
```

**完了条件**：`npm run dev` でクライアント（http://localhost:5173）に文字が出て、中継が8080で待ち受ける。`npm test` が通る。
**確認手順**：Claudeが示した手順どおりに実行。通ったら「初回コミットして」と言う。

## Day 1：ローカルで動く（移動・攻撃・防御・HP）

### Step 1-1 固定タイムステップの土台

```
SPEC.md 4章・5章・9章・16章を読んで。
shared/src/sim に、Phaser に依存しない固定60Hzのシミュレーションを作って。
- 状態: プレイヤー（位置・向き・HP100・シールド50・防御ゲージ100・入力）と弾のリスト
- 入力: 上下左右の移動、照準角度、攻撃ボタン、防御ボタン
- 1ステップ関数: step(state, inputs, dt) → 新しい state（純関数）
- 移動速度は balance.ts の「画面横断1.5秒」から算出する
- まずは1キャラ分。武器はピストルのみ（毎秒3発・ダメ6・マガジン8・リロード1.2秒）
- 四方を壁で囲んだ長方形フィールド。壁を抜けない
Vitest で「1秒で画面幅の2/3進む」「壁を抜けない」「毎秒3発しか撃てない」「8発でリロードに入る」をテストして。
client 側はまだ触らないで。
```

**完了条件**：`npm test` が通る。
**確認手順**：テスト結果の出力を見せてもらう。

### Step 1-2 Phaserで描画・操作

```
Step 1-1 の sim を client の Phaser で動かして。
- WASD移動、マウスカーソル方向に照準、左クリックで発射、スペースで防御
- 見た目は SPEC.md 14章の「暗め背景＋ネオン発光」。キャラは図形（速=鋭い三角）でよい
- 自キャラ直下に HP/シールド/防御ゲージの小バー（13章）
- 描画は sim の状態を補間して表示し、sim は 60Hz 固定で回す（CLAUDE.md の原則）
- 動かない的（HP100の四角）を1体置き、弾が当たると HP が減って数字がポップする
私が確認する手順を書いて。
```

**完了条件**：ブラウザでキャラが動き、弾が出て、的のHPが減る。
**確認手順**：`npm run dev` → 5173 → WASDで動く／マウスで向く／クリックで弾／的に当てるとHPバーが減る。

### Step 1-3 防御・シールド・ライフスティール・中心ヒット

```
SPEC.md 5.1・5.3・5.4・16章を読んで、sim に以下を足して。
- 防御（スペース）: 持続ゲージ制。射撃被弾で25減、近接は今は無視。ゲージ0でガードブレイク0.6秒行動不能。非使用時毎秒15回復
- シールド50: 被弾なし2秒後から毎秒15回復。攻撃命中で与ダメの50%回復
- 中心ヒット: キャラ半径30%の内側に当たると1.5倍
- ピストルの距離減衰3段（6.1章の閾値）
- 被ダメ倍率は一旦 1.0
これらをすべて Vitest でテストして（仕様の数値をそのまま期待値にする）。
的が反撃しないので、ライフスティールは「自分が撃って当てたら自分のシールドが戻る」ことで確認できるようにして。
client 側はゲージバーの表示と、防御中はキャラの輪郭が太くなる表現だけ足して。
```

**完了条件**：テストが通り、ブラウザで防御中に弾が減衰され、ゲージが減るのが見える。
**確認手順**：Claudeの手順どおり。「スペースを押しっぱなしで敵弾を受けるとゲージが減る」は Day 2 で相手ができてから再確認。

Day 1 終了時にコミット＋PLAN.md更新。

## Day 2：2人が繋がる（中継・ルームコード・ホスト権威）

### Step 2-1 中継サーバー

```
SPEC.md 10章・11章を読んで。relay を実装して。
- ルーム作成: 6桁英数字のコードを発行して返す
- ルーム参加: コードで参加。最大4人。ルームが無ければエラー
- 中継: ルーム内の他の参加者へバイナリ/JSONメッセージをそのまま転送。内容は解釈しない
- ホスト: ルーム作成者。ホストが切断したらルーム内全員に通知してルーム解散
- 非ホスト切断: 他の参加者に通知するだけ
- 状態はメモリ上のルーム表だけ。DBなし
- メッセージ型は shared/src/net に定義して client と共有する
Node のテストか簡単なスクリプトで「作成→参加→転送→ホスト切断で解散」を自動確認して。
```

**完了条件**：自動確認が通る。
**確認手順**：出力を見せてもらう。

### Step 2-2 ロビー（作成／参加）

```
client にタイトル画面とロビーを作って（SPEC.md 13章の画面フロー）。
- タイトル: 「ルームを作る」「コードで参加」の2ボタン
- 作成するとコードが大きく表示され、コピーできる
- 参加は6桁入力欄と「参加」ボタン
- ロビー: 参加者一覧（誰がホストか分かる）と「開始」ボタン（ホストのみ押せる）
- キャラ選択・bot追加・キー設定は今回は置かない（枠だけ）
見た目は最低限でよい。動作確認手順を書いて。
```

**完了条件**：ブラウザ2枚で、片方が作成したコードでもう片方が参加でき、両方のロビーに2人表示される。
**確認手順**：ブラウザを2つ（通常＋シークレット）開き、作成→参加→両方に2人出る→ホスト側の「開始」が押せる。

### Step 2-3 ホスト権威の同期

```
SPEC.md 10章の構成で、試合中の同期を実装して。
- ホスト: 全員の入力を受け取り、shared の sim を 60Hz で回し、状態スナップショットを 20Hz で全員に送る
- 非ホスト: 自分の入力を 60Hz で送り、受け取ったスナップショットを補間して描画する。今日はクライアント予測なし（補間のみ）
- ホスト自身も同じ sim を使う（分岐は isHost だけ）
- 2人ぶんのプレイヤーを sim に持てるようにする。弾の当たり判定はホストだけが行う
- 相手キャラは敵チーム色（赤の輪郭）で描画する
- 切断: 非ホストが落ちたらそのキャラを消して継続。ホストが落ちたら「ホストが切断しました」と出してタイトルへ戻す
遅延補正・予測は2週間目標なので今回はやらない。動作確認手順を書いて。
```

**完了条件**：2枚のブラウザで相手の動きと弾が見え、当てると相手のHPバーが減る。
**確認手順**：片方でWASDを動かすともう片方で動いて見える／片方が撃つともう片方にも弾が見える／当てると相手HPが減る／シークレット側を閉じると通常側で相手が消える。

Day 2 終了時にコミット＋PLAN.md更新。

## Day 3：勝敗が出る

### Step 3-1 残機・リスポーン・勝敗

```
SPEC.md 5.4・4章・16章を読んで、1vs1のルールを実装して。
- 残機: 個人3機。HP0で1機消費。リスポーン3秒、復帰後1秒無敵（攻撃すると解除）
- 撃破した側は HP+10（上限まで、シールドは回復しない）
- 試合時間2分。時間切れは 残機数 → 残HP（シールドは含めない）→ 引き分け
- 残機が0になったら試合終了
- リスポーン位置はフィールドの対角
判定ロジックはすべて sim（純関数）に置き、Vitest でテストして。
client には残り時間と残機をキャラ直下の小バー付近に表示して。
```

**完了条件**：テストが通り、ブラウザで撃破→3秒後に復帰→3回倒すと終了する。

### Step 3-2 リザルトと再戦

```
SPEC.md 13章・14章を読んで、最低限のリザルト画面を作って。
- 勝敗（WIN / LOSE / DRAW）を大きく表示
- 「再戦」ボタン: 同じメンバーでロビーに戻らず即再戦（ホストが押すと全員に反映）
- 「タイトルへ」ボタン
- 撃破時の演出は今日は「0.3秒スロー」だけ。それ以外の演出は2週間目標
動作確認手順を書いて。
```

**完了条件**：試合終了→リザルト→再戦で2試合目がすぐ始まる。

### Step 3-3 仕上げとレビュー

```
サブエージェントを使って、今の差分を SPEC.md の 4章・5章・10章・16章と照らし合わせてレビューして。
「仕様と違う」「仕様にない挙動」「ホスト権威の原則を破っている箇所」だけを報告して。スタイルの好みは報告しないで。
報告を受けたら、私に一覧で見せて。直すかどうかは私が決める。
```

その後：

```
指摘のうち [番号] を直して。直したら npm test と npm run typecheck を実行して結果を見せて。
docs/PLAN.md を「3日目標 完了」に更新し、2週間目標のチェックリストを SPEC.md 15章から作って。コミットして。
```

**完了条件**：テスト・型チェックが通り、PLAN.mdに2週間目標が並んでいる。

## 困ったときの定型文

| 状況 | 貼る文 |
|---|---|
| エラーが出た | 「これを実行したらこのエラーが出た：[貼る]。原因を調べて直して。直したら同じコマンドを再実行して結果を見せて」 |
| 動くけど違う | 「[操作]をすると[今の挙動]になる。仕様では[SPEC.mdの章]のとおり[期待する挙動]のはず。直して」 |
| 何をしているか分からない | 「今何をしているか、非エンジニア向けに3行で説明して」 |
| 大きく変え始めた | Escで止めて「その変更は計画にない。理由を説明してから進めて」 |
| 2回直しても直らない | `/clear` → 「[症状]が起きる。関係しそうなファイルは[名前]。原因を特定してから直して」 |
| 進捗を確認したい | 「docs/PLAN.md を見て、残りを一覧で出して」 |
